1) Посмотреть статус подов:

   kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

2) Посмотреть логи (как приложение стартует, идут ли миграции):

   kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -f

3) Достучаться до сервиса:

{{- if eq .Values.service.type "ClusterIP" }}

   ClusterIP — сервис доступен только внутри кластера. Для локальной проверки
   с твоей машины используй проброс порта:

       kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "file-service.fullname" . }} 10001:{{ .Values.service.port }}

   и открой:  http://localhost:10001/health

{{- else if eq .Values.service.type "NodePort" }}

   NodePort — сервис открыт на узлах кластера. Узнай порт:

       export NODE_PORT=$(kubectl get svc -n {{ .Release.Namespace }} {{ include "file-service.fullname" . }} -o jsonpath='{.spec.ports[0].nodePort}')
       export NODE_IP=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[0].address}')
       echo "http://$NODE_IP:$NODE_PORT/health"

{{- else if eq .Values.service.type "LoadBalancer" }}

   LoadBalancer — внешний IP выдаётся облаком, может занять минуту:

       kubectl get svc -n {{ .Release.Namespace }} {{ include "file-service.fullname" . }} -w
{{- end }}

{{- if .Values.ingress.enabled }}

   Ingress включён. Адреса:
   {{- range .Values.ingress.hosts }}
       http://{{ .host }}{{ (index .paths 0).path }}
   {{- end }}
{{- end }}

4) Если поды падают — самое полезное:

   kubectl describe pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
   kubectl logs    -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} --tail=200

5) Удалить релиз целиком:

   helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}
